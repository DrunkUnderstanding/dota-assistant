## 12. 界面改版：网页 + Electron（2026-10-22）

玩家反馈（原话）：「看着不太美观」。看了 Overwolf 插件的做法后，玩家在两条路线里**选了 B**：
学 ow-electron 的做法，但用普通 Electron，做透明、置顶、鼠标穿透的窗口，界面用 HTML/CSS 写，Python 继续做识别和推荐。
另一条路线（保留 Qt，只改样式）没选。

**为什么不直接用 Overwolf / ow-electron**：Overwolf 的游戏内叠加层要把界面画进游戏画面，通常的说法是要注入游戏进程，
这违反第 1 节的安全底线；它的游戏事件还要 Overwolf 按应用单独开通。普通 Electron 窗口盖在「无边框窗口」模式的 Dota 上就够了，
不碰游戏进程。从 Overwolf 学的是**设计**：深色底配金色强调色、到处都有英雄头像、推荐做成卡片（头像、胜率、胜率条、理由标签）。

**结构**（见第 3、4 节）：`live.Live` 就是原来的 `ui.App` 去掉 Qt，逻辑逐条对应；`webui.py` 起本机服务；
`electron/main.js` 只负责开窗口。所有改状态的操作都排进 `Live` 的同一个工作线程，因为 mss 的截屏句柄不能跨线程用，这样也省了加锁。
推荐理由从拼好的字符串改成分段（`Suggestion.reason_parts()`），`reason()` 输出的文字不变，网页按理由种类上色。

**实现假设（非玩家原话）**：
- 叠加层窗口高度直接拉到屏幕底部，卡片内容多高就画多高，空白处透明且鼠标穿透；每 3 秒 `moveTop()` 一次，防止被游戏压到下面（不抢焦点）。
- 控制面板默认 1140×780；关掉控制面板 = 退出助手。
- 界面不用前端框架、不打包，`web/` 下就是原生 HTML/CSS/JS（ES module），改完刷新页面就生效。
- 演示（`demo`）不再自动把每一步存成截图（旧版会存到 `shots/demo_*.png`）。

**验证情况**：`tests/test_webui.py` 全过，覆盖结构化视图、主控操作、本地服务（含路径穿越）、SSE 推送。
用真实数据起服务，无头 Chromium 截图看过控制面板、叠加层和补全下拉，页面没有报错。
**2026-10-22 开发机实跑**（4K 双屏、200% 缩放）：`demo` 弹出了 Electron 叠加层，透明、置顶、不进任务栏都正常。
发现两个问题并已修：① 4K 200% 下逻辑宽度只有 1920，0.80×1920+420 伸出屏幕 36，卡片右边被切掉 → `main.js` 把位置收回屏幕内；
② npm 11.6 装完没下载 Electron 本体（安装脚本没跑，原因没查）→ `start.py` 装完找不到就补跑 `node node_modules/electron/install.js`。
开发机没装 Dota，只把叠加层截图按真实位置贴到 Steam 商店的 Dota 截图上看了效果（`shots/ingame_*.png`）。
**还没做的**：盖在真正的 Dota（无边框窗口）上方实测（第 6 节第二项）。

**旧版 Qt 界面已删除**（`ui.py`，2026-10-22，玩家原话：「不要使用旧版QT界面作为兜底」）。没装 Electron 时只有 `run --browser` 浏览器预览，
叠加层盖不到游戏上。`requirements.txt` 里的 PySide6 现在只有校准窗口（`calibrate.py`）在用。

**下一步**：在游戏电脑上验证 Electron 叠加层（第 6 节第二项）。

**Overwolf 官方开源示例调研**（2026-10-22）见 [Overwolf调研.md](../docs/Overwolf调研.md)。要点：它们的游戏内叠加层全靠注入，不能用；
可学的是交互做法，比如热键切换「穿透 / 可交互」、拖动并记住位置、新一局自动清空局面。
官方不建议全屏透明窗口，而我们现在的叠加层窗口一直拉到屏幕底部，正是这种做法。
文末 5 条候选改进**待玩家确认，未实现**。

## 34. 出装推荐显示装备图标（2026-10-26）

玩家（原话）：「装备推荐功能最好是显示装备的图标而不是一个名字」。

**做法**：带装备的一行不再是纯文字，而是「片段」列表（`itembuild.chip` 一件、`itembuild.group` 并列几件、str 原样），
界面（`web/view.js` 的 `itemChip` / `partsHTML`）把装备画成图标，名字放悬停提示；`itembuild.text()` 拼回文字版，
语音、日志、命令行回放、交给 AI 的 `Brief.text()` 都用文字版，和以前一字不差（AI 打法缓存照样命中）。
- 换成图标的地方：本局要点「起手」「出装」「后期出装」（顺序一行、★ 针对装理由、提示几件、「前面的针对装到后期还没有先补」）；
  死亡 / 时间点卡片的「下一件」（下一件、格子满了先卖的、之后几件）；同一死法第 3 次的补装提示。
- 「缺口提醒」（`coach.check` 的 Need.text，例如「该出黑皇杖了」）还是纯文字，没改。
- 记号和文字版一致：★ = 针对这局（金框）、· = 之后常见（半透明）、✚ = 按死法补；图标后面的小字是中位购买时间（15′）或数量（×2）。
- 图标：`data.fetch_item_icons()` 按 OpenDota 装备常量里的图片地址从 Valve CDN 下到 `data/items/<key>.png`（88×64，配方不下，416 张，8 线程约 50 秒），
  `data.update` 会下；`start.ensure_data` 发现没有 `data/items` 目录也会补一次（不用等 3 天全量更新）。网页服务 `/items/<key>.png`。
  图下不到时界面显示名字。（顶栏小条的技能 / 金币图标是另一套：`/icons/`，2026-10-27 起也预下，见第 32.1 节）
- **2026-10-27 装备常量跟着刷新**：`data/opendota_items.json`（价格 / 合成 / 图标地址）以前只在没有时下一次（10-22 下的），之后一直不更新，
  版本改价格 / 出新装备会跟不上（「还差多少金」、合成树、新装备图标都靠它）。现在 `data.update` 每次先 `fetch_items_const` 重下再下图标。
  当时核对：旧文件里知识库 257 件物品一件不缺，还没出问题。

**2026-10-27 过了一遍「死数据」**（玩家问还有哪些能提前下好）：启动 / 3 天全量更新已经提前准备的：英雄表、选人识别头像、选人网格图（本机游戏文件）、
装备常量 + 图标、知识库、大招神杖 / 魔晶写法、顶栏图标、大数据 / 分位置 / 个人数据。选人后才联网的只剩：
本局要点的 STRATZ 三项（`brief.fetch_hero` / `coach.fetch_bench` 按「英雄 × 位置」、`brief.fetch_curves` 一份，都缓存 3 天，实测 1.3~6 秒，策略时间里做完不挡人）、
AI 打法（看双方阵容，40~50 秒，没法提前）、复盘命令拿比赛录像（开发用）。前两项是统计不是死数据，全英雄 × 5 个位置预拉要上千次 STRATZ 请求，没做。

**验证**：单元测试（文字版不变、片段里的装备 / 分组、「回家买」卡片带 parts、`/items/` 路径穿越 404）；
真实知识库 + STRATZ 建了一份卓尔一号位的本局要点，用 `view.js` + `base.css` 在无头 Edge 里截图看了中期 / 后期 / 起手 / 「回家买」：
图标、时间、箭头都对；折行时「→」跟着下一件到下一行行首（不会孤零零挂在上一行行尾）。图标尺寸（33×24）是实现假设，玩家没确认。
**Electron 实跑（2026-10-26，同第 32.1 节那次 `demo`）**：起手、中期出装（6 件、折两行）、后期出装、后期「提示 · 黑皇杖 / 白银之锋」、死亡卡片「下一件 / 格子满了先卖 / 之后」
都是图标，叠加层和面板里的图全加载、没有退回写字；日志 / 语音仍是文字版。**没在真实对局里看过**。
注意：名字只在悬停提示里，叠加层平时是鼠标穿透的（只有锁和 × 接鼠标），**在游戏里多半悬停不出名字**，认不出的图标只能去控制面板里看。

## 42. 顶栏计时开关（2026-10-30，控制面板「叠加层」卡片）

玩家需求（原话）：「现在的战斗过程当中的买活和英雄大招计时的叠层应该允许有一个设置开启和关闭的按钮控制一下」。

以前只能改 `config.toml` 的 `buyback_timer` / `ult_timer` 再重启，而且两个都是 false 时 Electron 干脆不开顶栏窗口。
- **控制面板**：「叠加层」卡片底色下面加一行「顶栏计时」，两个开关「买活」「对面大招」，点了**马上生效**（局内顶栏小条跟着出 / 收）、写进 `config.toml`（注释原样保留）。
  走 `set` 动作（`key = buyback_timer / ult_timer`，`TimersMixin.set_timer`），快照的 `settings` 里带这两项给面板画勾。
- **怎么马上生效**：`_bb_show` 改成只表示「在局里」，开没开在用的时候现看 cfg：`buyback_view` 两个都关就 `show: false`（顶栏整条不画、全点穿）；
  只关买活 → `buyback_on: false`，买活小条收起、大招小条照常；只关大招 → `_ult_of` 给 None。买活自动记（截图认顶栏）也只在买活开着时跑。
- **关掉时这局已经在走的倒计时不清**，再打开接着显示；买活关着时点小条（例如脚本 / 热键以后接进来）提示「买活计时关着，控制面板「顶栏计时」里打开」。
- **Electron 顶栏窗口总是开**（`main.js` 不再看 `buyback_timer` / `ult_timer`，`/api/config` 也不再给这两项）：不然启动时两个都关、局内再打开就没有窗口画。
  两个都关时页面什么都不画，可点区域为空，整条点穿。

**验证**：单测 `test_timer_switches`（开关马上改快照、写 config.toml、关着点小条不记、两个都关整条收起、再开接着显示原来的倒计时）；全部单测、`check_isolation`、`browser_check.py` 6 个页面无报错。
**Electron 实跑（2026-10-30，开发机两块 4K、缩放 2；临时运行目录，config.toml 两个都设 false 起；假 GSI 局内 15 分钟；CDP 只读页面状态，
点击是给 Electron 窗口 PostMessage 鼠标消息——玩家桌面上 QQ / VS Code 盖在面板上面，没抢前台；页面收到的是 isTrusted 的 pointerdown / click）**：
起来时顶栏窗口在、什么都没画 → 真点「取消」关掉新装自动弹的设置 → 点「买活」：顶栏出 10 个买活小条、config.toml 变 true →
点「对面大招」：对面 5 个大招小条 → 点顶栏夜魇第 2 个买活小条：末日使者开始 8:00 → 关「买活」：买活小条收起、大招小条还在 → 再开：末日那条倒计时还在 →
两个都关：顶栏整条空、config.toml 两行都是 false（注释还在）。Electron 日志只有一条开发机原有的 `chrome_100_percent.pak` 加载报错，和这次无关。

## 46. 选人叠加层放不下就上下滚 + 「推荐」「针对这局」能收起（2026-10-30，`web/overlay.html` + `web/view.js`）

玩家需求（原话）：「选人界面的信息高度做成可滚动的吧，就是叠层的显示视窗大小不会因为排版变化，但是要保证最低的左右宽度够，然后高度不够的时候不缩小字体左右排布，搞成可滚动的，针对手和推荐手应该也可以展开和折叠，展开高度不够以后允许滚动」。

- **不再缩小**：选人推荐（`draftHTML` 输出里标题栏下面包一层 `.ov-body`）不走第 22.1 节的 zoom，字号不变，也不会因为缩小后 CSS 宽度变大而变成左右两栏（两栏只看窗口真实宽度 ≥640，玩家自己拉宽才有）。
  卡片最高到窗口底（`max-height: 100vh`），标题栏和右上角锁 / × 不动，下面 `.ov-body` 上下滚；内容不够高时卡片照旧按内容高。滚动条 6px 金色，放在卡片右边留白里（`scrollbar-gutter: stable` + 负外边距），有没有滚动条排版一样宽。
  局内卡片（本局要点 / 提醒 / 「如果选它」）照旧放不下就整体缩小（在游戏里滚不方便）。
- **滚的位置**：`renderOverlay` 重画前记下 `.ov-body.scrollTop`、重画后放回，每秒的快照 / 局面变化不会把人弹回顶上。
- **固定状态下怎么滚**：叠加层大部分地方是点穿的，滚轮只在本来就可点的地方（推荐卡片、剩余位置、顶栏格子等）有用；另外能滚的时候滚动条那 10px 也报成可点区域，可以按住拖。
  滚出去的元素按滚动区裁剪后再报可点区域（不然看不见的卡片还挡着游戏），滚动时重报。分路、标题这些照样点穿，滚轮也不吃。
- **推荐组收起**：「推荐」「针对这局」（以及以后别的推荐组）标题右边「▴ 收起 / ▾ 展开 3」，收起后一排小头像 + 胜率（第一推荐金边），点小头像照样是「如果选它」；收起了哪几组按组名存在页面的 localStorage（`ov-folded-groups`），换局、重开助手都保持；控制面板预览同源，跟着一起收。（2026-11-02 起改成默认全部收起、记展开了哪几组，见第 50 节）
- **最窄 400**（原来 300，`main.js MIN_WIDTH` + `consts.OVERLAY_WIDTH`）：不缩小以后，无头浏览器量的结果是 380 以下顶栏 5 格 / 对位那行出界，380 时「针对这局」卡片的四字名被截成三个字，400 完整。以前存的更窄的宽度启动时收成 400（Python 那边当无效、用 config 的 420）。

**验证**：全部单测、ruff、编译、`node --check`、`check_isolation`（只有正在跑的助手写的 `shots/gsi`）、`browser_check.py` 无报错；行为快照这台机器没有。
无头 Edge（临时运行目录、真实统计数据，同第 44 节阵容）：420×700 卡片 696 高、内容 1686 滚动区 640，滚轮 400 → `scrollTop` 400、标题栏不动；458×915（玩家现在的大小）真点（CDP 鼠标事件）「推荐」收起 → 3 个小头像、存进 localStorage、重载后还收着，再收「针对这局」→ 内容 624 放得下、没有滚动条、卡片按内容高；点小头像 → 「如果选冥魂大帝 · 一号位」；720×600 两栏一起滚、没缩放；可点区域全在窗口内、能滚时多一条滚动条。
Electron（隔离服务、单独 profile）：起来无报错，未缩放；玩家在测试实例上自己解锁拖到右边、固定，两组都收起了（收起只能在固定状态点，说明固定时按钮能真点到）。**我的 `mouse_event` 脚本跑到一半发现玩家正在用电脑（光标下是 VS Code / Unity），停了**：滚轮 / 拖滚动条没用真鼠标测。
