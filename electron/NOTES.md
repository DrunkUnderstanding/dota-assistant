## 14. 叠加层拖动 / 固定（2026-10-22）

玩家需求（原话）：「这个叠层应该允许我手动拖动位置，然后有一个固定按键可以固定位置，解锁固定以后又可以拖动」。

- 开关就在叠加层卡片右上角：一把锁（SVG 图标），关着 = 固定，打开（金底）= 可拖动；热键 `hotkey_lock`（默认 F7）同样切换。
  玩家第二次反馈（原话）：「这个叠层可拖动位置的按钮应该直接放在叠层上，这个为什么会放到主界面窗口当中，而且应该用一个锁和一个解开的锁来解释」，
  所以控制面板上的「解锁位置」按钮和解锁时的文字提示条都去掉了。解锁后叠加层强制显示（隐藏过也显示），卡片加金色虚线框。
- 固定状态下鼠标移到按钮（锁、×）上才接点击，其余地方照样穿透。
- 拖动：解锁后只有鼠标在卡片上时窗口才接鼠标，空白处照样穿透；
  按下后 Electron 主进程每 16ms 读系统光标位置移动窗口（不用页面坐标，免得高 DPI 换算出错），松开后把窗口高度重新拉到屏幕底部。
- 固定：再点一下锁或按 F7，恢复穿透（只剩按钮能点）。
- 位置和固定状态存在 `data/overlay.json`（占 `monitor` 那块屏的比例），优先于 `config.toml` 的 `overlay_x/y`；启动时会把位置收回屏幕内。
- 状态由 Python（`Live.overlay_locked`）统一管，快照里 `overlay.locked` 推给叠加层页面，页面再通过 `electron/preload.js` 告诉主进程。

**实现假设（非玩家原话）**：热键默认 F7（Dota 里如果占用了就改 `hotkey_lock`）；按住卡片任意处都能拖，不单设拖动把手；默认是固定状态。
**验证情况**：单元测试覆盖解锁 / 固定 / 位置保存和重启沿用。开发机实际起了 Electron（第一版，带文字提示条）：预加载脚本生效，
用 `SetCursorPos` 移动光标模拟拖动，窗口跟着移了 (-150, +80)，位置存回 Python。改成锁图标后同样在 Electron 里验证过，见下。
**没验证**：真手按住拖动（系统鼠标捕获 + hover 转发）、盖在 Dota 上时的表现，要在游戏电脑上试。

**关闭按钮**（2026-10-22，玩家原话：「这个叠层应该有一个关闭按钮，我可以随时关闭，当然快捷键也没问题」）：
- 叠加层右上角锁的右边加了 ×，和锁一样固定状态下也能点。动作 `close_overlay`：弹着局内提醒就只关提醒（和 F8 一致），
  否则 `user_hidden = True` 收起叠加层；解锁着点 × 会顺便固定（解锁状态会强制显示，不固定就关不掉）。
- 局内提醒卡片原来自带的 ×（`.ov-close`）在叠加层上隐藏，由右上角的 × 代替，避免两个 × 挨着；控制面板预览里照旧显示。
- 快捷键沿用 F8（`hotkey_toggle`），再按一次或点控制面板「显示叠加层」重新打开。
- **注意**：关闭后 `user_hidden` 一直保留，下一局选人也不会自动弹出来，要按 F8。玩家如果觉得不方便，可以改成新一局选人开始时自动恢复。
- 验证：单元测试 `test_close_button`；Electron 里点 × 后叠加层收起且按钮跟着隐藏，F8 重新打开；弹着提醒时 × 的提示变成「关闭这条提醒」，点了只关提醒（截图看过）。

**按钮点不到的 bug（2026-10-22 修）**：玩家反馈（原话）：「为什么我现在刚开的一个界面，这个叠层的锁定和关闭选中不了」。两个原因：
1. 启动时只写了 `setIgnoreMouseEvents(true)`（没有 forward），页面收不到鼠标移动，不知道鼠标到了按钮上；
2. 更根本的：靠页面 mouseover / mouseout 切穿透不可行——窗口一从穿透切到接鼠标，Chromium 立刻补发一次 mouseout，
   页面以为鼠标离开按钮又切回穿透，循环下去按钮永远点不到。之前用 CDP 调 `click()` 的测试绕过了鼠标，所以没发现。

**现在的做法**：页面报「可点区域」（固定时是锁和 × 的矩形，解锁时是整张卡片；`overlay:hit-rects`，布局变了才重报），
Electron 主进程每 30ms 读系统光标位置，在区域里就接鼠标、不在就穿透（状态变了才调 `setIgnoreMouseEvents`），完全不依赖页面鼠标事件。

**验证（真鼠标输入）**：测试脚本用 `mouse_event` 发真实的鼠标移动 / 按下 / 抬起（`SetCursorPos` 不经过系统鼠标输入，不算数；
脚本要先 `SetProcessDpiAwareness(2)`，否则 200% 缩放下坐标会错），并且先确认窗口已经不穿透才按下，避免点到下面的程序。
在开发机（4K 200%）上逐项通过：卡片外和固定时卡片中间都穿透；真点锁 → 解锁；真按住卡片拖动 → 窗口移动 (-100, +50) 并保存位置；
再点锁 → 固定，卡片中间恢复穿透；真点 × → 叠加层收起，原位置穿透；F8 打开后 × 又能点。**还差盖在 Dota 上实测。**

## 23. 叠加层底色 / 不透明度可调（2026-10-23）

玩家反馈（原话）：「现在的这个叠层的透明度有点高了，透明度还有颜色这种应该可以自己设置」。

- 控制面板右侧「叠加层」预览下面加了两行：**不透明度**滑块（30%~100%）和**底色**（7 个深色预设 + 彩色方块 = 自己挑颜色）。
- 拖滑块 / 挑颜色时只改内存，游戏里的叠加层和预览马上跟着变；松手 / 点色块才写进 `config.toml`（`overlay_opacity`、`overlay_color`，保留注释）。
  动作是 `set`（`key` = `overlay_opacity` / `overlay_color`，`save: false` = 只预览）；快照里 `overlay.style` 推给叠加层页面，`view.js applyOverlayStyle` 设 `--ov-fill`。
- 只改卡片底色，文字、标签、头像不跟着透明。不透明度低于 0.3 收到 0.3；颜色必须是 `#rrggbb`。
- 默认不透明度 0.85 → **0.95**；开发机的 `config.toml` 也改成了 0.95。

**实现假设（非玩家原话）**：放在控制面板而不是「设置」窗口（要边调边看）；只调底色，没开放强调色（金色）和文字颜色；预设只给深色，因为文字是浅色。
**验证**：单元测试 `test_overlay_style`（预览不落盘、保存保留注释、下限、非法颜色报错）；无头 Chrome 截图看过面板控件，
发 `save: false` 把不透明度改 50%、底色改深蓝后，叠加层页面截图确实变了，`config.toml` 没动。**没在 Electron / Dota 上方看过实际效果。**

**真窗口演示（2026-10-23，`demo`）**：分路、你这路怎么打、本局要点都正常弹出；AI 打法（新提示词）47 秒、折合 $0.19，写出了围绕同路的建议
（「被压时让巫妖给你套冰霜魔盾」「束缚击放空后趁冷却上前补刀」），每条出处都核对通过。

### 22.1 叠加层适配屏幕 + 可拉宽（2026-10-23）

玩家反馈（原话）：「这个叠层可能会超出显示范围，需要适配一下屏幕，允许扩大宽度」。以前窗口固定 420 宽、高度到屏幕底，内容更长就被切掉。
- **拉宽**：解锁（F7 / 锁）后卡片右边缘有个金色拉手，按住左右拖改宽度（`main.js` 的 `startResize`，左边不动、不超出屏幕右边、最窄 340）。
  松手后宽度和位置一起报给 Python（`overlay_moved` 多了 `width`），存在 `data/overlay.json`，下次启动沿用；只拖位置不会丢宽度。
- **宽了分两栏**（`base.css` 容器查询，卡片 ≥640px）：选人卡片左 = 阵容 + 分路，右 = 你这路怎么打 / 推荐 / 威胁；本局要点的小节分 2 列（≥960 分 3 列）。窄的时候顺序和以前一样。
- **放不下就缩小**（`overlay.html` 的 `fitHeight`）：卡片比窗口（到屏幕底）高时，从 100% 往下按 5% 一档试 CSS zoom，取第一个放得下的，最小 55%。
  宽度按缩放换算，缩小后卡片仍然占满窗口宽，缩到一定程度会自动变两栏。不按比例一步算出：分栏会让高度突变，实测一步算会缩过头（0.55，其实 0.65 就够）。
- **窗口收在屏幕里**：启动、拖完、拉完都把位置和宽度收回当前屏幕（以前拖出右边就出去了）。
- 验证：单元测试（宽度存取、校验、重启沿用）；无头 Chrome 用真实视图测 fitHeight（窗口高 1000 / 700 / 600 → 0.95 / 0.70 / 0.65，满宽不溢出）和两栏排版。
  **Electron 里只确认了启动无报错**：叠加层开着防截图保护，截不到，拉手拖动的手感、缩放后的点击区域要玩家实际看。

### 22.2 拖到副屏 + 自由改宽高（2026-10-29）

玩家反馈（原话）：「这个助手为什么不能调整位置，我放到副屏就又弹回来了，还有叠层的大小控制不自由，需要能够自由改变宽度和高度」。
原因：拖完 `saveBounds` 一律按 `config.toml` 的 `monitor` 那块屏收边界，拖到副屏松手就被收回主屏；高度固定拉到屏幕底，只能改宽。
- **跨屏**：松手时光标在哪块屏，叠加层就归哪块屏（`stopDrag` 用 `screen.getDisplayNearestPoint`），位置按那块屏的比例存，另存那块屏左上角坐标
  （`overlay.json` 的 `screen`，Electron 逻辑像素，副屏在左 / 上时是负数）。启动时按左上角找回那块屏，找不到（拔了副屏）就放回 `monitor` 那块并记一条 WARN。
  拖动中不收边界，宽高跟位置一起设（跨不同缩放的屏时防 Windows 改窗口大小）。
  **截图（mss）和买活 / 大招计时条照旧用 `monitor`**（计时条要盖在 Dota 顶栏上，不跟叠加层走；以前它跟叠加层用同一个 `display`，现在分开成 `gameDisplay`）。
- **宽高**：解锁后整个窗口画成金色虚线框（框 = 叠加层占的地方，卡片放不下会在框里整体缩小，同 22.1），框里任意处按住都能拖；
  右边拉手改宽、下边改高、右下角一起改。最窄 300（原来 340）、最矮 160。拉过高度才存 `height`，没拉过照旧到屏幕底；拖位置时高度不变，往下拖到底会停住（不缩高度）。
  解锁时可点区域是整个窗口（原来只有卡片），固定后照旧只有按钮那几样。
- 验证：单元测试（高度 / 屏幕存取、校验、只拖位置不丢）；行为快照只有解锁提示语变了（已 `update-snapshot`）。
  Electron（隔离实例，临时目录 + 单独 profile）：存了不存在的副屏 `(-1920,0)` + 高 500 → 启动日志 WARN 并放回主屏、窗口 420×500；解锁后虚线框和三个拉手位置对、卡片 0.85 缩放放进框里。
  **没验证**：真鼠标拖动 / 拉宽高（测的时候 Dota 在前台、光标下是 dota2.exe，停了没点）、跨屏（开发机单屏）。
