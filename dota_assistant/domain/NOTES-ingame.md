## 11. 局内缺口提醒（2026-10-22，`coach.py`，`python -m dota_assistant coach-sim <比赛编号...>`）

玩家需求（原话）：「AI 在战斗过程当中，有办法告诉我这把我缺少什么东西吗」；先修标签误判，再用模拟试。
**现状：模拟版完成（录像重放），实时版（接 GSI）未做。**

**先修了知识库标签**（`kb.py`）：
- 注释（notes）多是「能不能打到隐身单位」「被沉默时会不会打断」这类交互说明。现在能力类标签只看正文，
  只有 `NOTES_OK`（克敌机先、无视技能免疫、不可驱散、怕破坏、无视闪避）也看注释。「隐身」改成要求「进入 / 获得 / 变为…隐身」。
  修后「隐身」从 43 条降到 15 条，全是真隐身；露娜、灰烬之灵、沉默术士、帕吉不再被标隐身。
- 「沉默」不再被英雄名「沉默术士」误命中；「缴械」排除自身被缴械（钢背兽、獸）；「缠绕」排除给队友用的（寒冬飞龙极寒之拥）。

**判断逻辑**（全部数字对数字、原文对原文，不用大模型；阈值都是实现假设，在 `coach.py` 文件头）：
| 提醒 | 条件 |
|---|---|
| 黑皇杖 | 对面 ≥3 个英雄有控制（眩晕 / 沉默 / 缠绕 / 妖术 / 缴械）且自己英雄没有技能免疫；时间 = 同分段黑皇杖中位时间 +4 分钟，没有数据时 25 分钟。附「X 的 Y 无视技能免疫，黑皇杖挡不住」 |
| 金箍棒 / 血棘 | 对面有提供闪避的技能，且自己没有克敌机先、也没有玩家规则；小黑会改成开局提示「不用专门出」 |
| 反隐 | 对面有隐身技能 → 开局提示让辅助带粉；原文写「不会被反隐手段发现」的（斯拉克暗影之舞）注明粉没用 |
| 核心装晚了 | 同分段多数局会买、≥1500 金的装备，比中位购买时间晚 4 分钟还没有（合成后的也算有） |
| 节奏 | 10/15/20… 分钟正补低于同分段平均的 80%（否则看经济） |

提醒时机：死亡时 + 每 5 分钟；每次最多 2 条；同一条隔 6 分钟才重复，最多 2 次。
同分段数据来自 STRATZ `heroStats.stats(groupByTime)`（每分钟平均正补 / 经济）和 `itemFullPurchase`，缓存在 `data/bench/`。

**昨晚 6 局的模拟结果**（玩家 20:39~00:20，一号位）：
- 两局卓尔：20 分钟提醒魔龙枪（同分段一般 15 分钟，实际 21:16 / 26:05）；25 分钟提醒黑皇杖（实际 35:02 / 43:26）；
  原力法杖（实际 45:14 / 32:58）。开局都提示「射手天赋自带克敌机先，不用专门出金箍棒」。**两局 10 分钟正补（43 / 50）都不落后**。
- 敌法师（赢的那局）：10 分钟正补 30、15 分钟 60，落后同分段约 26~29%。
- 幻影长矛手：10 分钟正补落后 21%；对面 3 个控制但整局没黑皇杖。
- 斯温：黑皇杖 22 分钟就出了，没触发。

**更正**：之前出装复盘时说「同分段一号位 10 分钟通常 60~70 刀」，那是凭记忆说的，**是错的**。
STRATZ 实测超凡～冠绝卓尔一号位 10 分钟平均正补 43，敌法师 42。玩家两局卓尔 10 分钟正补（43 / 50）是平均水平，问题在装备节奏。

### 11.1 实时版（2026-10-22）

玩家决定：**死亡时 + 每 5 分钟**检查；有缺口就在叠加层**弹卡片，可以关**；**先不念**（`config.toml` 的 `coach_voice = true` 能打开）。

数据流：Dota ──GSI──▶ `gsi.py`（`items` 订阅已打开，**要重新 `gsi-install`**）──▶ `Live.coach_tick()`（每秒一次，跟识别同一个循环）──▶ `Coach.tick()` ──▶ 叠加层卡片。
- **开局**（GSI 进入 PRE_GAME / GAME_IN_PROGRESS、换了 matchid）：后台线程 `coach.prepare()`，敌方阵容用选人时格子里的（识别 / 手填），
  自己的英雄用 GSI，位置用控制面板的。有开局提示（自带克敌机先、对面能隐身等）就先弹一张「开局提示」。
  格子里没敌方阵容时照样建，只看出装节奏，并在开局提示里说明。中途重连进来，已过的时间点不补报。
- **死亡**：看 `player.deaths` 计数涨没涨（不看 `hero.alive`，采样间隔长也不会漏）。**时间点**：`map.clock_time` 跨过 10/15/20…分钟。
- **卡片**：`kind=notice` + `closable`，黑皇杖那条用警示色。弹出时会取消「隐藏叠加层」；关法：F8（有卡片时 F8 先关卡片）、
  叠加层右上角「×」（固定状态下只有鼠标在「×」上时窗口接点击，其余穿透）、控制面板右侧预览里点「×」。比赛结束 / 回到选人自动收起。
  局内没卡片时叠加层不显示（和以前一样）。

**假 Dota 跑通（开发机，比赛 9054096051 卓尔，`demo --speed 60`）**：选完人后录像按 GSI 格式推到本地端口，叠加层依次弹出：
开局「风行者有闪避，但射手天赋自带克敌机先」→ 20 分钟魔龙枪 → 25 分钟黑皇杖（对面 5 个控制）→ 30:00 死亡时原力法杖 →
32:00 死亡时再提黑皇杖 → 比赛结束收起。和 `coach-sim` 的结果一致。加速时标题里的时间会比整点晚一点（每秒检查一次，1 秒 = 1 游戏分钟），真实速度下没这个问题。

**还没确认**（要在游戏电脑上 `gsi-dump` 看真实推送）：
- `player.net_worth` 有没有：没有的话节奏只比正补（`check()` 里经济那条不触发）。
- `items` 下的格子名是不是 `slot0~8` / `stash0~5`（目前按这个解析，`teleport0` / `neutral0` 不算）。
- 演示里装备用的是「到这一刻买过的全部东西」；真实 GSI 只给身上现有的，合成掉的零件靠 `item_tree()` 向上找，应该没问题。

**内容和来源**（STRATZ 数据缓存在 `data/brief/`，3 天）：

### 15.1 AI 打法（2026-10-22，`gameplan.py`，`brief-sim <比赛编号> --ai`）

## 18. 死亡复盘（2026-10-23，`death.py`）

玩家需求（原话）：「需要增加一个死亡的时候的提示，总结一下刚才是怎么死的」。

**数据**：GSI 玩家视角只给自己英雄的东西，所以复盘只看自己：`gsi.GameState` 对局中留最近 60 秒的推送（GSI 线程写、主控线程读，带锁），
GSI 配置多订阅了 `abilities`（**要重写配置并重开 Dota**；`start` 现在只要配置内容和模板不一样就重写，以前只看端口）。
死亡判断沿用局内提醒的 `player.deaths` 计数。GSI 不给「谁杀的、对面来了几个」，这里也不猜。

**卡片内容**（和局内缺口提醒合成一张，标题「死亡复盘 · 时间 · 第 N 次」，缺口列在「还缺」下面）：
| 行 | 怎么算 |
|---|---|
| 一句话结论 | 从死前往回找「这波」的起点（血量明显回升过的地方之后、最后一次血最多的时刻），按顺序取第一条：硬控（眩晕 / 妖术）占这波 ≥ 一半 →「被控死」；≤3 秒从半血以上到死 →「被瞬间打爆」；掉到 30% 以下后又撑了 ≥4 秒 →「残血拖太久」；往回 20 秒都在掉血 →「持续掉血」；否则「X 秒内从 Y% 血被打死」 |
| 状态 | 眩晕 / 妖术 / 沉默 / 锁闭 / 缴械 / 破坏各多少秒（两次推送之间按前一次的状态算）；开着技能免疫、开着雾 |
| 保命装备 / 技能 | 手挑的保命装备（黑皇杖、跳刀、推推、微光、魔杖 ≥5 层…）+ 自己英雄的大招和跑路技能（知识库原文关键词：闪烁 / 冲刺 / 无敌 / 技能免疫 / 隐身…，全英雄跑过一遍，有少量误判）：冷却变长 = 用了；不在冷却且有没被控的时刻 =「当时是好的，没用上」（警示色）；一直被控 =「被控着用不了」；没被控也放不出来 =「蓝不够？」；在冷却单独列。跳刀按官方原文「受到来自敌方英雄或肉山的攻击时，闪烁匕首将在3秒内无法使用」处理：≤3 秒的冷却不算用过，一直挨打用不了单独说，挨打前那一下没跳不算失误 |
| 其他 | 死前蓝量 <15%；死在哪（地图坐标粗分：自家 / 对面半场 × 上中下路 / 野区 / 高地）；复活秒数、掉了多少钱、买活够不够 |

**显示**：复活后（`hero.alive` 变回 true，且卡片至少显示了 3 秒）自动收起；死亡时弹的缺口卡片也一样。F8 / × 照样能关。默认不念（跟 `coach_voice`）。
每次死亡把那 60 秒推送原样存到 `shots/deaths/<时间>.json`（最多 50 份，卡片内容也在里面），用来核对字段和调阈值。

**实现假设（非玩家原话）**：阈值全在 `death.py` 文件头（往回 20 秒、瞬间 3 秒、残血 30%、硬控占一半…）；保命装备清单手挑；
地图分区是按地图大小估的线；复活后自动收起（以前死亡弹的缺口卡片要手动关）；和缺口提醒合成一张而不是两张。

**验证**：`tests/test_death.py`（爆发 / 被控 / 回血后重新算起点 / 残血 / 保命装备用了没用 / 跳刀挨打禁用 / 全程被控 / 没血量字段 / 历史裁剪）、
`tests/test_webui.py::test_death_recap_then_respawn`（主控：死亡弹卡片、缺口接在后面、存推送、复活收起）。
GSI 字段名对照了 Dota2GSI（C#）的解析代码：`hero.health / max_health / mana_percent / stunned / hexed / silenced / muted / disarmed / break / magicimmune / smoked / xpos / ypos / respawn_seconds / buyback_cost / buyback_cooldown`、
物品 `cooldown / can_cast / charges`、技能 `level / can_cast / passive / cooldown / ultimate`。**没在真实推送里见过**（以前存的都是选人阶段的）。

## 25. 出装推荐（2026-10-25，`itembuild.py` + `coach.plan`）

玩家反馈（原话）：「现在的装备推荐功能没有特别的好」。问了哪里不好，玩家四项全选：**不看对面、千篇一律**；**针对装太少**；
**不告诉我下一件买什么**；**提醒时机或说法不好**。依据选了「统计 + 知识库规则」（不用大模型）。

**数据修正（这次最大的问题）**：`coach.fetch_bench` 原来的 `itemFullPurchase` 没传 `matchLimit`，STRATZ 默认只返回买的人多的时间段，
卓尔一号位只回来 5 件前中期装（猎鹰战刃、魔龙枪、夜叉……），**黑皇杖、蝴蝶都没有**——所以以前关键装备千篇一律、黑皇杖只能用 25 分钟兜底。

### 25.1 按死法补装（2026-10-25，`itembuild.death_pick` + `Coach.on_death`）

**做法**：死亡复盘（第 18 节 `death.analyze`）除了文字，现在还给结构化结果（`Recap.cause / secs / immune / saves / owned`），
`itembuild.DEATH_RULES` 按顺序匹配第一条，挑一件装备：
| 死法 | 条件 | 候选（按顺序挑第一件；跑路装挑买得多的） |
|---|---|---|

| 被沉默死 | 沉默 ≥2 秒、没被锁闭（锁闭时物品也用不了） | 幻影斧「可以使用幻影斧移除多种负面效果」、散魂剑「驱散佩戴者」、黑皇杖「施加弱驱散」；文字注明「能驱散的沉默」 |
| 被瞬间打爆 | 复盘判「被瞬间打爆」 | 永恒之盘、微光披风（魔法护盾） |

**`death-sim`**：`python -m dota_assistant death-sim [文件...]` 拿 `shots/deaths/` 里存下的真实死亡推送重放（位置按英雄本分段最常打的位置猜，同一场按顺序累计）。

## 28. 本局要点按阶段弹（2026-10-26，`brief.STAGES` + `Live._stage_tick`）

玩家反馈（原话）：「现在的打法推荐感觉是应该在不同的阶段弹出，然后可以在我关闭以后重新找到原来的打法推荐，而不是一开局就一股脑地塞给我」。

|---|---|---|
| 对线期 | 说明、对线（分路 / 对线数据 / 对线提示）、起手、对面要防 | 对线期、对线劣势时 |
| 中期 | 强势期、出装 | 中期 |
| 后期 | （无） | 后期 |

### 31.1 买活自动记：截图认顶栏（2026-10-26，`buybackscan.py`）

玩家（原话）：「买活这种事件不会弹出提示吗，弹出提示的时候截个图然后AI自动记录或者你做一个程序自动记录，买活是正常的全图广播信息吧」。
是全场广播（音效 + 头像下面的金币堆，Fandom），但金币堆长什么样、在哪我们没截到过；**也没查到买活会不会在聊天框 / 击杀栏出一行字**。
所以先用能从已知画面推出来的办法，不用大模型（OCR 一次 0.3 秒、只在有人死时认；大模型几秒到几十秒、要花钱）：
1. 比赛中（0:00 后、没暂停、`buyback_timer` 和 `buyback_auto` 都开）每次 `coach_tick`（约 1 秒）截一帧 Dota 窗口；截到的是整屏（Dota 切出去了）就跳过。
2. 每格头像（y 6~38、左右各 24，位置同 topbar.html，按图高 / 1080 缩放）饱和度中位数 < 12 算灰（死了），连续 2 帧才算；复活要中位数 ≥ 20 连续 2 帧（2026-10-26 实战后改的，原来是平均 < 40，见本节末）。
3. 刚灰起每帧把那一格（头像 + 下面到 y 76）给 Windows OCR（`roles.ocr`）认复活倒计时 T，算「该在 这一帧 + T 复活」；
   **两次算出来差 ≤ 2 秒才算数**，最多认 5 次。变回彩色时比该复活的时间早 ≥ 3 秒 = 买活 → `Tracker.start`（玩家已经点了就不动）。
   没认出来（倒计时个位数、OCR 不灵）就不自动记。自己那格跳过（GSI 有）。
4. 每次复活存「刚死时给 OCR 的那一格 + 复活那一格」到 `shots/buyback/<时间>-<阵营><第几个>-<buyback|respawn|unknown>-<秒>.png`，留最近 200 张；日志里每次死 / 复活都有一行「买活自动记：…」。
OCR 预处理（`for_ocr`）：只留白字（亮、低饱和）→ 头像下面那截有字就只要那截 → 切到字 → 字高放到 40 → 横着复制 3 份隔开。

早先的处理方式会把 10 认成 1、14 认成 4，所以加了两次核对。

## 76. 出装「别买」：对面 2 个以上无视技能免疫的控制，黑皇杖不推；对面能显形时提示隐身装（2026-11-09，`coach.bkb_piercers` / `Need.avoid`）

**起因**：同行 gg-go-next 有「别买」类针对装规则（「黑皇杖挡不住肢解」「斯拉达看穿微光」），玩家要做，接知识库原文核对。

**黑皇杖（大数据 + 本局，两种依据都有）**：
- 大数据是第 69 节黑皇杖研究：核心 25 分钟前出黑皇杖、同英雄同经济下比钱花在别的装上，对面无视技能免疫的控制 0 个 +0.6 ±1.3，2 个以上 −3.2 ±1.8（差 −3.8，z = −3.5，过校正；30 / 35 分钟同方向）。
- 本局：`coach.bkb_piercers` 和研究脚本 `c_an.py` **同一个计数规则**（不是先天技能、作用于敌方或无目标、官方字段 immunity = 对敌方无视技能免疫、并且只能强驱散或带眩晕 / 妖术 / 沉默 / 缠绕定身标签；数的是技能个数，不是英雄个数），算出来正好是研究列的 21 个英雄。为此知识库条目加了 `strong_dispel` / `innate` / `target_team` 三个官方字段。
- 对面合计 ≥ 2 个（`BKB_PIERCE_AVOID`）：核心不再出「对面控制多，出黑皇杖」，改成一条「别买」（`Need.avoid`）：不催（`check` 跳过，同分段核心装「还没出」也不催黑皇杖），出装顺序 / 「下一件」里拿掉，本局要点出装那页第一页列一行「这局别出 ✗黑皇杖：……」；辅助只在「对面要防」里说一声。只有 1 个时照旧推，尾巴写「X 无视技能免疫，黑皇杖挡不住」。
