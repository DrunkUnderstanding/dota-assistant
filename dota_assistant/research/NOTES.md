## 2.1 回测结果（2026-10-21，`python -m dota_assistant backtest`）

样本：统计数据截止（match_id 9053619429）之后随机抽的 2555 场超凡～冠绝天梯全英雄选择，共 25550 手选人，
选人顺序和每人位置来自 STRATZ。每一手只用「轮到他时能看到的」信息重放。完整报告在 `data/backtest_report.txt`。

| 实际选的英雄在推荐里排第几 | 这手所在队伍胜率 |
|---|---|
| 第 1 | 58.1% ±4.2 |
| 第 2~3 | 55.3% ±2.5 |
| 第 4~10 | 53.1% ±1.4 |
| 第 11~20 | 50.4% ±1.2 |
| 第 21 以后 | 47.3% ±0.9 |

- 先选（第 1~4 手）：推荐前 3 胜率 56.3%，排 20 名以后 47.9%；后选（第 7~10 手）：54.9% vs 44.7%。
  区分度（排名与胜负的相关系数）先选 0.053、后选 0.075：后选更准，但先选也有用。
  **更正**：第一次回测（2449 场，另一批随机样本）先选那行是 52.5% vs 49.2%，当时据此说「早选几乎没用」，
  那是小样本噪声（推荐前 3 只有 453 手、区间 ±4.6），换一批样本就不成立了。
- 只看最终阵容预测胜负：英雄强度 56.8% → 加克制 57.8% → 加配合 57.9%。
- 样本里天辉胜率约 54.6%（地图偏向），阵容预测没建模这一项；选人推荐不受影响（同一手的候选都在同一边）。
- 这是相关不是因果：选得好的人可能也打得好，排名靠前组的胜率差里有一部分来自玩家水平。

**对线加权 / 早选防反制（`backtest --tune`，一半对局调参、一半验证）**：

| 改动 | 结果 |
|---|---|
| 对线对手克制权重 ×1.5 / ×2（`W_LANE` 0.5 / 1.0，敌方位置按其主位置推断） | 区分度略降（0.051 → 0.048~0.049），**没用** |
| 反制风险扣分（`W_RISK` 0.03~0.3，取最克我的 1 / 3 / 10 / 30 个未选英雄） | 变化 ±0.003，在噪声（约 ±0.01）以内，**没用** |

所以两项都默认关闭（常数保留在 `engine.py`，以后有新想法可以接着试）。保留了一个纯提示：
对面还剩 ≥3 手、且有未选英雄克我 ≥4 个百分点时，推荐理由里显示「易被反制：XX(+5.2%)」，不影响排名。

可能的原因（推测，未验证）：克制数据不分位置，单独放大对线对手只是放大噪声；
天梯里对面后手未必真会针对你（每个人优先选自己的位置和英雄），所以「可能被反制」平均下来影响很小。

**个人数据不参与排名（2026-10-24 / 25 玩家决定）**：个人胜率 `W_ME` 0.5 → 0，熟练度 `FAMILIAR_BONUS` 0.08 → 0，
手写英雄池 `POOL_BONUS` 0.04 → 0。排名只看英雄打这个位置的强度 + 克制 + 配合；推荐不再分「你的英雄 / 其他选择」，
合成一个「推荐」榜。理由里的「你近期 N 局 X%」只是显示。（2026-10-26 起又分成「推荐 + 针对这局」两组，见第 26 节）
自己在这个位置打过 ≥3 局的英雄仍然跳过位置筛选（只影响能不能上榜，不加分）。回测本来就没覆盖这几项（样本是别人的对局）。

**冷门英雄 / 冷门位置降权（2026-10-25 玩家要求；10-30 查了玩家生涯局数，绝活只占 0.5~0.9 点，现在最多扣 2 点，见第 43.2 节，下面是当时的做法）**：米波、维萨吉、一号位拉席克这类场次少、绝活玩家多的，胜率虚高。
`base_at` 现在按「这个英雄打这个位置的局数」（总局数 × 位置占比）向 50% 收缩，`K_PICKS = 10000` 局时只算一半；
克制 / 配合的期望值仍用原始胜率。3001 场样本外回测扫了几档：

| K_PICKS | 区分度（全部 / 前 4 手 / 后 4 手） | 一号位第一 | 中单前三 |
|---|---|---|---|
| 0（改前） | 0.0554 / 0.0468 / 0.0745 | 拉席克 58.4 | 米波 56.8、维萨吉 55.9、力丸 55.0 |
| 5000 | 0.0516 / 0.0431 / 0.0717 | 拉席克 54.1 | 米波 54.6、殁境神蚀者 54.3、力丸 53.8 |
| **10000（采用）** | 0.0501 / 0.0415 / 0.0697 | 幽鬼 53.0 | 殁境神蚀者 54.1、米波 53.4、力丸 53.0 |
| 20000 | 0.0486 / 0.0406 / 0.0676 | 主宰 52.7 | 殁境神蚀者 53.8、龙骑士 52.4、米波 52.3 |

区分度略降，在噪声（约 ±0.01）以内；而且回测样本里选米波的多半就是米波玩家，本来就偏向绝活英雄，这点下降是预期的。

## 10. 大模型选人盲测（2026-10-21，`python -m dota_assistant backtest-ai`）

玩家提出的验证方法：取历史对局选人进行到一半（第 3~6 手、双方都已有英雄）的时刻，让 AI 推荐，再看推荐和实际胜负的关系。

**做法**：每场对局取一个时刻；候选 = 实际选的英雄 + 这个位置（分段出场占比 ≥10%）随机 11 个，打乱。
AI 用玩家的 Claude Code 订阅无头调用（`claude.exe -p --safe-mode --tools "" --json-schema …`，Opus 5.5），
只给位置、双方已选、禁用、候选；不给对局 id / 胜负 / 实际选择 / 工具。对局都在 2026-10，晚于模型训练截止。
统计引擎在同一批题、同一组候选上也排一次。结果累积在 `data/ai_backtest.jsonl`。

**Windows 坑**：经过 npm 的 `claude.cmd` 调用时，空参数（`--tools ""`）和多行参数会被 cmd.exe 弄丢，
导致系统提示 / JSON schema 失效、还加载了项目 CLAUDE.md。现在直接调 `node_modules/@anthropic-ai/claude-code/bin/claude.exe`。

**300 个时刻的试点结果**（折合 API 价约 $3.3，走订阅额度）：

| 排序方式 | 区分度（实际选的排名越前 ↔ 越赢） |
|---|---|
| AI（Opus 5.5） | +0.108 |
| 统计引擎 | +0.076 |
| 两者平均名次 | +0.097 |
| **只按「这个英雄在该分段打这个位置的出场占比」** | **+0.178** |

样本 300 的噪声约 ±0.11，**以上差别都不显著**。但拆开看很有信息量：
- AI 的排序和统计引擎几乎不相关（平均 0.01），和「位置出场占比」相关 0.63；引擎和位置胜率相关 0.77、和出场占比只有 0.06。
- 也就是说 AI 主要在按「这个英雄是不是这个位置的常规选择」排，而单靠这一项的区分度反而最高。
- 当时推测「选了不常打这个位置的英雄的队伍更容易输」，**已在大样本上否定**（2026-10-22）：
  - 同样的出题方式在 2555 个时刻上（换 8 组随机候选）：只按出场占比的区分度平均 0.040，统计引擎 0.048。
    300 题里的 0.178 是小样本噪声。
  - 把出场占比加进引擎打分（log / 线性、多档权重），一半调参一半验证：最多 +0.001，权重稍大就变差。**没有采用。**
- 所以试点里 AI 的 +0.108 也很可能有相当部分是噪声。要判断 AI 有没有真本事，只能跑大样本。

**下一步**：如需结论，跑全部约 2555 个时刻的 AI 盲测（折合 API 价约 $28，走订阅额度，可能碰到速率上限，
`backtest-ai --moments 2555` 会接着已有结果续跑）。样本 2555 时噪声约 ±0.04，AI 要比引擎高出 0.05 以上才算真有优势。

**全量结果（2026-10-22，2555 个时刻，折合 API 价约 $27 + 试点 $3.3，走订阅额度）**：

| 排序方式 | 区分度（噪声约 ±0.039） |
|---|---|
| AI（Opus 5.5，无资料、凭自身 Dota 理解） | +0.032 |
| 统计引擎 | +0.055 |
| 两者平均名次 | +0.055 |

| 实际选的英雄排在 | AI 排序下胜率 | 统计引擎排序下胜率 |
|---|---|---|
| 前 3 | 52.4% | 55.2% |
| 第 4~8 | 51.9% | 49.1% |
| 第 9~12 | 46.5% | 49.1% |

**结论**：AI 没有比统计引擎更准（反而低 0.023，差距在噪声内，但方向不利）；把 AI 和引擎平均也没有提升。
试点的 +0.108 是小样本噪声。AI 与引擎的排序几乎不相关（0.00），说明 AI 的「Dota 常识」和真实对局统计是两回事。
**决定：选人排名不用大模型**，继续只用统计引擎。大模型留给「解释理由」「出装 / 局内建议」这类需要综合原文资料的场景，
而且必须喂知识库原文和统计数字，不让它凭记忆判断。

## 28. 对线优劣：能不能猜、屯野 / 莲花怎么分（2026-10-26，`lanestate.py`）

玩家（原话）：「屯野和抢莲花都可以亮，是两种不同的选择而已，如果要说具体情况应该按照当时对线的优势劣势情况来分配」；
问怎么判断优劣时说「杀敌死亡次数、等级差这种」，要用数据验证，三步都做。

**1. 回测**（`python -m dota_assistant lane-test`，报告存 `data/lane_report.txt`）：选人回测那批样本外对局（超凡～冠绝），STRATZ 能取到前 12 分钟逐分钟数据的 1523 场、15230 人次。
目标 = STRATZ 这条路的对线结果（天辉 / 夜魇胜、大胜算优，平局算平），从自己这边看。两折交叉，概率都是样本外的。全部：优 38% / 平 25% / 劣 38%。
| 看什么 | 3:00 猜对 | 3:00 把握 ≥60% 的占比 / 其中猜对 | 6:00 猜对 | 6:00 把握 ≥60% 的占比 / 其中猜对 |
|---|---|---|---|---|
| 一直猜「劣」 | 38% | — | 38% | — |
| 只看自己（击杀 / 死亡 / 助攻 / 等级，GSI 拿得到） | 48% | 13% / 67% | 57% | 37% / 74% |
| + 本路等级差（对面等级要看顶栏 / 计分板） | 50% | 19% / 71% | 61% | 52% / 76% |
| + 本路击杀差 | 51% | 23% / 71% | 62% | 54% / 77% |
| 参考上限：再加本路经济差 | 56% | 34% / 73% | 66% | 58% / 80% |
「劣」的概率是校准的（6:00 只看自己：猜 0~20% 的实际劣 12%，60% 以上的实际劣 75%）。
玩家说的两个指标单看就很有区分度（6:00）：本路等级差 ≤-1 → 81% 劣、≥+1 → 81% 优；本路击杀差 ≤-2 → 77% 劣、≥+2 → 80% 优；自己死 ≥2 次 → 61% 劣。
**结论**：3:00 太早，只有少数局看得出来；6:00 只看自己就有用，加上对面等级还能多出 15 个百分点的「有把握」局。平局基本猜不出来。

**2. 屯野 / 莲花**（三 / 四 / 五号位，按 6:00 时模型「看着」的优劣分组；屯野 = 5:53 那组，莲花 = 6:00 那朵在背包里见到）：
| 当时看着 | 屯了野 | 拿了莲花 | 都没有 |
|---|---|---|---|
| 劣 | 195 人：最终劣 69%，比赛胜率 43% | 609 人：劣 48%，胜率 49% | 3781 人：劣 65%，胜率 44% |
| 优 | 177 人：优 63%，胜率 54% | 736 人：优 72%，胜率 56% | 3307 人：优 60%，胜率 56% |
3:00 方向一样（劣：屯野 劣 53% / 莲花 41% / 都没有 54%）。**只是相关**：拿得到莲花的人本来就离池子近、血线健康；
莲花只在背包里见到的才算（整局用过莲花的 6409 人里 3:00 背包里见到 1409 人，拿了马上吃的漏掉了，混在「都没有」里）。
另一个发现：三 / 四 / 五号位在 2:53、5:53 屯野的只有约 4%，比野区提醒（每分钟都提醒）频繁得多，可能要减。

**3. 实战记录**：`live._lane_log` 在 3:00 / 6:00 / 10:00（到点 20 秒内）把自己的 GSI `player` / `hero` 原样、血蓝比例、背包、当时亮的提醒记进 `data/lane_log.jsonl`；
`python -m dota_assistant lane-review` 去 STRATZ 取赛后数据（按好友代码找自己，找不到按英雄），逐个时刻列：当时自己的数据、只看自己猜的、看全本路猜的、实际对线结果、屯野 / 莲花做没做。
STRATZ 解析要等一阵；本地 / 机器人局查不到。

**数据字段**（STRATZ match，实查）：`stats.level` 是每级的时间；`campStack` 第 i 个是到第 i 分钟累计；`inventoryReport` 第 i 个是第 i-2 分钟（按莲花第一次出现在 5 / 8 / 11 推的）；`itemUsed` 只有整局次数。
**注意**：这次 `lane-test` 调了 `backtest.fetch_matches`，统计数据的 match_id 范围变了，`data/backtest_matches.json` 被重新抽成了 1523 场（以前是 2555 场），第 2.1 / 22 节的数字是旧那批的。
**还没定**：卡片上要不要写「对线看着劣（把握 X%）」、要不要从截图认对面等级，等玩家看完结果再说。

## 60. 组合研究：精灵老鹿（艾欧 + 拉席克）（2026-11-04，`docs/research/io-leshrac/`）

一次性研究，不进产品代码。玩家要的：这个组合的出装、节奏、每个时间点大概率干什么、对线结果、推哪座塔，最后要一张「小地图」样式的网页看。

- **结论**（详见 [research/io-leshrac/README.md](../../docs/research/io-leshrac/README.md)）：两人同队 5466 局、胜率 63.4%，比期望高 8.5 个百分点。主流打法是拉席克 1 号位 + 艾欧 5 号位、双人走优势路。节奏是 6 分钟奥术鞋后边打边推、10.8 分钟第一次降临、11.3 分钟慧光后推塔伤害翻倍、15~20 分钟最强、拖过 40 分钟变差。对线结果和单独英雄差不多，赢主要靠中期降临 + 拉席克推塔。
- **页面**：`python docs/research/io-leshrac/build_page.py [--minimap 小地图.png]` 生成「精灵老鹿小地图.html」。图标读本机 `data/` 缓存、缺的现下；生成的网页和截图都不进 git。
