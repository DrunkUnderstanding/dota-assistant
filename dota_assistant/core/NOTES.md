## 17. 日志（2026-10-22，`log.py`）

玩家需求（原话）：「帮我把这个软件做好日志管理」。以前全程没有日志：出错只在状态栏显示一行「出错：…」，
后台线程（本局要点 / AI 打法 / 局内提醒）的异常、Electron 页面报错、语音进程报错都看不到，开发机和游戏电脑又不是同一台，没法远程排查。

**怎么用**
- 运行类命令（`start` / `run` / `demo` / `update` / `calibrate` / `label` / `gsi-dump` / `backtest*` / `*-sim` / `kb update`）每次启动在 `logs/` 下写一个
  `<时间>-<命令>.log`；查询类命令（`suggest` / `kb hero` / `say` / `logs`）不写文件，只在控制台显示警告，免得把有用的日志挤掉。
- 只留最近 30 个文件；单个文件超过 5 MB 滚动成 `.log.1` / `.log.2`（开着助手打一晚上也不会无限长）。`logs/` 不进 git。
- 看日志：`python -m dota_assistant logs`（最新一份的末尾）、`logs --open` 或控制面板「打开日志」（打开文件夹）。
- `config.toml` 的 `log_level = "DEBUG"` 会多记每秒一次的识别分数、每次 GSI 推送的时间 / 死亡 / 正补，调 `match_threshold` 时用。

**记了什么**（INFO 级别）
- 开头：命令行、Python / Windows 版本、代码版本（git）、完整配置（token 只写「已设置」）；
- 主控：校准 / 模板数、每次局面变化（双方英雄、位置、推荐前五和胜率）、播报的话、识别结果变化（每格名字 + 相似度，认不出的写 `?最像的`）、
  网页操作、热键、弹出的卡片内容、本局要点 / AI 打法 / 局内提醒的开始和耗时；
- GSI：第一次收到推送（带顶层字段）、阶段 / 阵营 / 英雄 / 比赛编号变化；
- Electron：版本、每块屏的分辨率 / 位置 / 缩放、叠加层位置、拖动 / 解锁、页面脚本报错、页面崩溃 / 加载失败（main.js 往 stdout 写「级别 内容」，`webui._pipe_electron` 收进来）；
- Claude Code 每次调用的耗时、折合价格；联网 429 限速、STRATZ 报错、连接重试（urllib3）；语音进程报错（例如没有中文语音包）、热键注册失败。

**出错怎么记**
- 程序 bug（操作出错、后台线程异常、主线程崩溃）带完整堆栈，用 `sys.excepthook` / `threading.excepthook` 兜底；状态栏提示后面加「（详情见日志）」。
- 网络问题（`requests` 异常、`data.APIError` = STRATZ / explorer 自己报错）只记一行，不记堆栈。
- 控制台（「启动助手」黑窗口）只显示本程序的 WARNING 以上，而且不带堆栈；第三方库的警告只进文件。
- STRATZ token 在输出前替换成 `***`（包括异常堆栈里），单元测试覆盖。

**实现假设（非玩家原话）**：每次启动一个文件 + 留 30 个；INFO 默认；控制台只显示警告；「打开日志」按钮放在控制面板操作栏「清空」左边。

**验证**：`tests/test_log.py`（写文件、token 打码、控制台不带堆栈、DEBUG 开关、清理旧文件、后台线程异常、Electron 输出转发）。
游戏电脑上玩家用「启动助手」实跑了一次（2026-10-22 21:49），日志里看到的东西本身就是几条验证结论：
- **GSI 第一次接上真实游戏**：第一条推送只有 `draft` / `player` / `provider` 三个字段（没有 `map`），接着 `HERO_SELECTION → STRATEGY_TIME → TEAM_SHOWCASE →
  WAIT_FOR_MAP_TO_LOAD → PRE_GAME`，阵营 radiant、英雄 weaver 都对；策略时间开始时自动做了本局要点，进 PRE_GAME 后准备了局内提醒。
- **那一局比赛编号一直是 0**（可能是练习 / 机器人局，没确认）。主控按比赛编号判断「换局了没」，如果天梯也是 0 或者连着两局都是 0，
  第二局不会重做本局要点 / 局内提醒——**要在天梯里确认**，是的话改成按「回到选人阶段」判断换局。
- 当时 STRATZ 返回 503，本局要点 / 局内提醒照常出来（只是没有 STRATZ 数据）；AI 打法 29 秒、折合 $0.062。
- 5 个热键都注册成功，F10 截图实际按过；屏幕 1920×1080、缩放 100%。
- Electron 44 的 `console-message` 旧参数写法会报弃用提示、开发模式 CSP 安全提示每次启动刷两条：都已改（只用事件对象；设 `ELECTRON_DISABLE_SECURITY_WARNINGS`），**改完还没重启验证**。

## 36. 找 Dota 目录认了空壳，GSI 连不上、阵营全按天辉算（2026-10-27）

现象（玩家原话）：「别人使用的那个 exe 版本……似乎只能把自己识别到天辉」。

**朋友的日志**（两份，20:24–21:47 和 22:37）：
- `GSI 服务在 127.0.0.1:3000 等游戏推送` 有，`GSI 收到游戏推送` 一条都没有 → 端口没被占，游戏从没推过。
- GSI 配置写进了 `e:\steam\steamapps\common\dota 2 beta\…`，同一次启动导出网格图报 `找不到 e:\steam\…\game\dota\pak01_dir.vpk`。
  真装了 Dota 一定有这个主资源包（本机 `d:\softwares\steam\…` 核对过有）→ 那是挪库 / 卸载留下的空壳，游戏装在别处，配置写进去游戏不读。
- 以前 `find_dota` 只看 `game\dota` 文件夹在不在、先查 Steam 根目录，就认了空壳。
- 阵营「自动」、GSI 没连上时 `Live.side()` 是 None，`current_draft` 悄悄按天辉分友敌：人在夜魇时推荐等于对着自己队友算克制，界面只在标题写了「阵营未知」。
- 另外：他启动助手时 Dota 已经开着、整段没重开，就算写对了目录那次也不会生效。日志里他的顶栏识别分数大多 0.2~0.6，主屏 2560×1440，可能要重新校准（没处理）。

**改了什么**
- `gsi.find_dota / is_dota_dir / steam_libraries`（从 `start.py` 挪过来）：要有 `game\dota\pak01_dir.vpk` 才算 Dota；所有 Steam 库都查，空壳跳过并记一行日志。
  `install_cfg` 也只往真目录写；`ensure_cfg` = 配置不在 / 变了才重写。
- 新配置项 `dota_dir`（空 = 自动找）：控制面板「设置」多一节「Dota 目录」，填错（没有资源包）直接报错；选深一层（`…\game\dota`）、带引号也认；
  保存后马上重新找、把 GSI 配置写进去（提示要重开 Dota）。`gsi-install <目录>` 也会把目录记进 `config.toml`。
- 状态栏：没找到 Dota 目录显示「GSI 未连接 · 没找到 Dota 目录」（红点，点它跳到设置那一节）；找到了但没连上，鼠标悬停说配置在哪、检查启动项 / 先开助手再开 Dota。
- 阵营不知道时仍先按天辉分（`SIDE_FALLBACK`，总得有个分法），但：叠加层推荐卡片顶上一条黄条「不知道你在哪边，先当天辉（左边）是我方…」，
  控制面板两队标签变成「我方？/ 对方？」；GSI 中途连上 / 阵营变了，下一次 tick 就重新分友敌（以前要等识别结果变了才重算）。
- 启动窗口找不到 Dota 时说清楚怎么填目录。

**验证**：单元测试（空壳跳过、设置的目录优先 / 填错照样自动找、配置只写真目录、设置里填目录、状态栏两种说法、GSI 中途连上重分友敌——去掉 tick 里那行这个测试会挂）；
全部单测；本机 `find_dota()` 照样找到 `d:\softwares\steam\…\dota 2 beta`；无头 Chrome 截图看过控制面板（状态栏、「我方？」）、叠加层黄条、设置里的「Dota 目录」。
**没在朋友电脑上验证**，见第 7 节 0.3。
