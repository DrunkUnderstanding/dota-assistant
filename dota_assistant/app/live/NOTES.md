## 3. 架构

```
            ┌─────── app.update（每天一次，联网，经 sources.*）──────┐
            │ OpenDota explorer → 克制 / 配合矩阵  data/stats_*.json │
            │ STRATZ heroStats → 英雄分位置胜率    data/positions_*  │
            │ STRATZ player   → 你每局的英雄 / 位置 data/player.json │
            │ Valve datafeed + CDN → 中文名 / 头像  data/heroes.json, data/portraits/ │
            └───────────────────────────────────────────────────────┘

run（实时）：
  app.live.Live 工作线程每 scan_interval 秒（网页操作 / 热键也排进同一个线程的队列）
    └ should_scan？（自动识别模式 + 已校准 + GSI 说在选人阶段 / 没 GSI 时勾了持续识别）
        └ vision.capture.Screen.grab()（优先只截 Dota 窗口，找不到再 mss 截整屏）
          └ vision.recognize.recognize()：按 calibration.json 裁 10 个格子 → 和模板比相似度
            └ 连续两次结果一致才采用（躲开选人动画）→ 填进 Live.slots（控制面板的 10 个格子）
  格子（识别或手动）+ game.gsi（阵营、我选的英雄）
    └ domain.advisor.Advisor.advise() → domain.engine.Engine.suggest()
      ├ domain.advisor.render_view() → 状态快照 → app.webui 本地服务 SSE → 叠加层 / 控制面板网页
      └ domain.advisor.speech()：对面新选了谁 → game.speech.Speaker.say()
  界面：app.webui 起 127.0.0.1 随机端口 → 启动 electron/ 外壳开两个窗口加载 web/ 下的页面
```

**控制面板的 10 个格子是唯一的「当前局面」**：识别和手动输入都只是往里写，推荐只从格子读。
这样纠正识别错误、手动兜底、学习模板都是同一个入口。

**分层（2026-10-28 工程化重构后，`tests/test_layers.py` 强制）**：从低到高 `core` → `sources` → `kb` → `ai` → `domain` →
`vision` / `game`（平级）→ `research` → `app` → `cli`，只能 import 同层或更低层，`__main__` 只 import `cli`。
不留转发旧路径的空壳模块；跨模块共享的函数用 `模块.函数` 形式调用（例如 `http._get(...)`），测试只 patch 一处。
计划和每个名字的去处见 [refactor/PLAN.md](../../../docs/refactor/PLAN.md)、[refactor/moves.json](../../../docs/refactor/moves.json)、[refactor/layering.md](../../../docs/refactor/layering.md)。

## 37. 对面大招小条认错 / 缺：局内重识别把阵容冲掉了（2026-10-28）

现象（玩家原话）：「这一局的识别不对」「英雄大招都识别错了，有的还没有」。比赛 9064511724，我帕格纳。

**对面大招 / 买活小条的英雄从哪来**：全靠**选人时**顶栏头像识别填进的 10 个格子（`Live.slots`）。GSI 玩家身份不给对面英雄；
局内没有单独认英雄。所以选人时没认出 = 那一格没有大招小条，格子被冲掉 = 小条跟着错。

**这局日志 + 死亡截图（`shots/deaths/20261028-002624-0s.png` 顶栏）对出来的**：
| 时间 | 发生了什么 |

**改了什么**（`Live.scan` / `fill_slots`）：
- GSI 说已经出了选人 / 策略时间（出门、比赛中、赛后），顶栏识别直接不做；按 F9 状态栏写「进了游戏不能重识别…在控制面板对应格子里手动改」并记日志。
  没连 GSI 时照旧（不知道在哪个阶段）。（2026-11-01 收紧：GSI 这次推送过、或者找不到 Dota 窗口就不认，见第 48 节）
- 策略时间只往**空格子**补认出来的英雄（不换、不清已有的，也不补和别的格子重复的英雄），免得最后一手在选人结束前没来得及两帧对上就漏掉。
- 选人阶段不变。

**试过、没做**：局内直接认顶栏头像。用官方横版头像当模板、按买活那套几何裁局内头像，3 张局内截图 30 格：
对的那格分数 0.30~0.60、和第二名常只差 0.0~0.05，死了的头像（灰）全错，**不能用**。要做得另找模板（例如选人时就把认对的格子在局内的样子存下来学），或者只在「选人时已选走的英雄」里挑。

**验证**：单元测试 `test_webui.CoachLiveTest.test_no_top_bar_scan_after_draft`（局内 F9 不动格子且给提示、策略时间只补空格子、选人阶段照常整排写）；全部单测。
**没在真实对局里跑过**。

**为什么选人时没认全**（拿 `shots/` 里以前的截图重跑识别对照）：
- 大家选完、头像干净时（10-23 01:36 那张）10 格 0.73~0.91 全对，最低那格右上角盖着段位小徽章；选人进行中刚选的头像上盖着带数字的徽章（10-23 01:43 拉比克 0.63）。
  这局对面认出的 3 个也都不到 0.70（宙斯 0.66、撼地者 0.62、力丸 0.53），是靠网格核对（≥ 0.5）补上的；破晓辰星差一点没到 0.5。
- 第 5 格从选人开始到结束一直 0.27、分数没变过 = 那格头像在选人时根本没出来（局内那格盖着断线图标，推测那人一直断线，没截图证实）。
- 策略时间第一秒：6 格分数和之前一模一样，潮汐、主宰、夜魇第 5 格变了样子（0.3~0.5），整个策略时间都这样。可能是换了饰品（主宰 / 潮汐都有至宝），没截图，是猜的。
- 判断逻辑的毛病：认不出 = 空，「连续两帧一样才采用」对「两帧都空」也成立，画面一乱就把认对的清掉了（上面「策略时间只补空格子」挡住了）。

### 37.2 选人界面：看得出哪格没认出，在叠加层上帮认（2026-10-28）

玩家（原话）：「选人界面的时候如果有角色没有识别出来，我应该有办法知道你没有识别到，然后我可以帮助你识别」；
「你应该还要有一个类似记忆的系统，就是把之前纠错的内容记录下来」「下次就能识别到了」。

以前叠加层的「敌 / 友」只列认出来的英雄，没认出的格子直接不显示，玩家看不出少了谁；改要去控制面板。

- **顶栏对照**（`Live.slots_view`，`draft_view` 里的 `slots`；`view.js` 的 `slotsHTML`）：「敌 / 友」两行**固定 5 格**，从左到右和游戏顶栏一样。
  认出的是头像（点了能改，标题「XX认错了？」）；**金色闪的「?」= 这格有人选了但没认出**；虚线「空」= 看着还没选（也能点，游戏里已经有人的话直接填）；
  自己那格（GSI `team_slot`）金色底线、不能点，还没在格子里时用 GSI 的英雄。有「?」时下面一行写「N 格有人选了但我没认出」。
- **「?」怎么定**：策略时间起（GSI）人人都有英雄了，空着的都是「?」。选人阶段看这格**比这局第一次裁到的（`blank`）变了样、而且多出了彩色**（`_looks_picked`）：
